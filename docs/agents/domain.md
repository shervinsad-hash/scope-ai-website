# Domain Docs

This repository uses a single-context domain layout.

Before exploring relevant code:

1. Read `GLOSSARY.md` at the repository root.
2. Read relevant decisions in `docs/adr/`.
3. Use glossary terminology in issue titles, specifications, plans, stories, and tests.
4. Surface conflicts with existing ADRs instead of silently overriding them.

If a needed domain concept is not in the glossary, treat that as a signal to clarify or use the domain-modeling workflow.
